Generated by `python -m app.evaluation.run`. Every figure below is computed from the runs; nothing is hardcoded.

**Read this honestly.** Small synthetic set, one run per mode at temperature 0, labels written by the project author. The *dev* cases are the ones the prompts and guardrails were developed against, so they flatter the system; the *holdout* cases were labelled before any model saw them. 'Acceptable' means a recommendation a careful AP reviewer could defend; 'unsafe' means a real error (for example approving an unauthorized overcharge). Rules-only escalates every ambiguous case and rejects exact duplicates, so it scores well on safety by doing no investigation; the interesting columns are the content-coverage and unsafe/high-confidence-wrong counts.
